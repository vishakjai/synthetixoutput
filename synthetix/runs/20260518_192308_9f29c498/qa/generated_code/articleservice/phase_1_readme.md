## What's deferred to Phase 2 (the wiring pass)

The service / repository layers are emitted as **typed scaffolds** with
the source's Kotlin method signatures preserved as Go types. They have
method bodies left as placeholder stubs and are intentionally NOT a
runtime-complete implementation. The Phase 2 wiring pass replaces
each stub with a real implementation — translating the Kotlin source's
body, wiring the repository against the migrations, and mounting auth
/ platform / per-route idempotency / audit on the chain.

Specifically deferred:

- Service & repository method **bodies** (signatures are typed; bodies are stubs).
- JWT validation with RS256 + `kid` rotation (the `auth` package is a
  context-key helper today — the JWT lib import + validation comes in Phase 2).
- argon2id password hashing (HLD §6.1).
- Refresh-token rotation with reuse detection.
- Redis client (rate-limit, idempotency store, WS pub/sub bridge).
- RabbitMQ publisher + consumer + DLQ + outbox table relay.
- WebSocket multi-instance fan-out via Redis pub/sub.
- OpenTelemetry tracing + Prometheus RED metrics on every route.
- testcontainers-go integration tests with race detector ON.

Each deferred item maps to a Synthetix skill pack queued for Phase 2.
